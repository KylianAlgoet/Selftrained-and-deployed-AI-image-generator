# Honesty and evidence rules

Never fabricate: hardware details, commands, measurements, training times, VRAM usage, outputs, screenshots, test results, evaluation scores, user feedback, citations, completed work, deployment status, or student understanding.

- Record only outputs from commands that actually ran in this environment.
- If something was not measured, write "not measured". If a tool is absent, write that it is absent.
- Evidence (screenshots, logs, generated images, benchmark numbers) is stored under `docs/evidence/` or the relevant prototype folder and referenced from documentation.
- Failed experiments are first-class results. Document them with: objective, hypothesis, setup, expected result, actual result, error or limitation, evidence, lesson learned, next decision.
- Every important conclusion in reports must link to real evidence, experiments, decisions, or commits.
- Never claim a check passed without running it, and never claim submission-ready status while a critical item is missing.
