# Prototype 1 (M3) local inference stack - Python 3.11 venv at repo root (.venv).
# Kept separate from ml/requirements.txt (M2 dataset tooling) so the dataset
# pipeline stays installable without the multi-GB CUDA stack.
#
# INSTALL ORDER MATTERS. PyTorch comes from the official PyTorch index, not
# PyPI, because those wheels bundle their own CUDA runtime:
#
#   .venv/Scripts/python.exe -m pip install --upgrade pip
#   .venv/Scripts/python.exe -m pip install \
#       --index-url https://download.pytorch.org/whl/cu126 \
#       torch==2.13.0+cu126 torchvision==0.28.0+cu126
#   .venv/Scripts/python.exe -m pip install -r ml/requirements-inference.txt
#
# Why the pip upgrade is required: the venv shipped pip 22.3 (Python 3.11.0,
# Oct 2022), which rejects modern wheels whose metadata name is normalized with
# underscores ("expected 'typing-extensions', but metadata has
# 'typing_extensions'") and fails to resolve torch at all. Upgraded to pip 26.2.
#
# Why cu126 rather than matching nvidia-smi: `nvidia-smi` reports the DRIVER's
# maximum supported CUDA API version (13.3 on driver 610.88). That is NOT a
# toolkit version PyTorch must match - the wheel ships CUDA 12.6 and runs on any
# sufficiently new driver via CUDA minor-version compatibility. Verified on this
# machine: see docs/evidence/EXP-001/cuda-smoke-test.json (VERDICT: PASS,
# RTX 4060 Laptop GPU sm_89, fp32/fp16/bf16 CUDA matmul all correct).
# cu130 wheels also exist for this torch version and are the documented
# alternative; cu126 was chosen for the widest compatibility with the adapter
# and 8-bit-optimizer libraries needed in Prototypes 2-4.
#
# xformers is deliberately NOT installed: torch 2.x scaled-dot-product attention
# is the Diffusers default and needs no extra dependency.
#
# Resolved and verified 2026-07-30 on Windows 11, Python 3.11.0, RTX 4060 Laptop
# (8 GB). Full environment snapshot: docs/evidence/EXP-001/pip-freeze.txt.
